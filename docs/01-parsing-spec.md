# Summa 解析链路技术方案（纯视觉路线）

> 版本：v1.0 ｜ 2026-10-27
> 决策：不做双通道融合，不做文本层提取，全部依赖多模态模型直接读页面图像。
> 本文只描述这一条路线，不讨论备选方案的取舍。

> **实现现状（2026-10-28，应用 0.4.0）**
>
> 本文是目标方案。当前应用实现的是它的**单次调用简化版**，与本文的差异：
>
> | 本文方案 | 当前实现 |
> |---|---|
> | 三段式：结构扫描 → 定向精读 → 综合生成 | 一次调用，直接输出要义页 JSON |
> | PyMuPDF 渲染，Pass 1 约 100 DPI、Pass 2 约 180 DPI | 前端 PDF.js 渲染，统一宽 1400px（约 150 DPI），JPEG 质量 0.82 |
> | 全篇扫描 | 只送前 12 页 |
> | 输出 5.2 节结构（`findings` 三元组、每条带 `page`、`confidence`） | 输出简化结构：`findings` 为 `{value, label}`，不含 `page` 和 `confidence` |
> | `weak_fields` 标灰 | 未实现 |
>
> 三条质量规则（数值照抄、findings 只取正文强调、limits 只取作者自述）已写进当前 prompt。
> 当前的数据结构见 [开发指南 · 数据模型](../app/README.md#数据模型)。外部工具导入接受 5.2 节的完整结构，并转换为当前结构（见 [集成方案 · 数据契约](02-integration-spec.md#4-数据契约)）。
>
> 实现顺序上，下一步应先做第 10 节的评测，用数据决定是否值得上三段式。

---

## 0. 决策前提

- 模型：DeepSeek V4.1 Flash（`deepseek-flash`），原生多模态，1M 上下文，$0.14 / M 输入 token
- 不做本地文本层提取，不引入 GROBID / Docling / MinerU
- 不做数字回指校验链路，模型输出的数值直接采信
- 保留唯一一项低成本保险：**每条结论带页码**（见第 6 节）

这条路线换来的收益是管线极短——PDF 进，结构化 JSON 出，中间没有对齐、没有坐标映射、没有两套结果冲突消解。代价是数字准确率依赖模型本身，需要用评测数据摸清边界。

---

## 1. 架构

```
PDF 文件
  ↓  渲染（PyMuPDF, 100–200 DPI）
页面图像序列
  ↓  Pass 1：结构扫描（全篇，低 DPI）
章节地图 { 摘要 p1, 方法 p3–6, 实验 p7–11, 结论 p12 }
  ↓  Pass 2：定向精读（关键章节，高 DPI）
结构化抽取
  ↓  Pass 3：综合生成
要义页 JSON
```

三段式而非单次调用，是这个方案的关键设计，理由在下一节。

---

## 2. 为什么分三段而不是一次喂完

1M 上下文确实装得下 24 页，但**装得下不等于读得准**。单次调用有三个可观测的失效模式：

1. **中后段衰减**。模型对开头与结尾的抽取质量显著高于中间。论文的中间恰恰是方法与实验。
2. **分辨率与上下文的两难**。为了塞进整篇，只能降 DPI；降了 DPI，公式上下标和表格小字就读不清。
3. **错误无法隔离**。一次调用出一个 JSON，错了不知道错在哪一段，重试只能整篇重来。

分三段解决这三点：结构扫描用低 DPI 图便宜地定位，精读只对关键章节用高 DPI，出错时只需重跑单个章节。

---

## 3. 渲染参数

| 用途 | DPI | 格式 | 单页 token 估算 |
|---|---|---|---|
| Pass 1 结构扫描 | 96–110 | JPEG q85 | 700–900 |
| Pass 2 定向精读 | 180–200 | PNG | 2,500–3,500 |

渲染代码：

```python
import fitz  # PyMuPDF

def render(path: str, out_dir: str, dpi: int, fmt: str, quality: int = 85):
    doc = fitz.open(path)
    out = []
    for i, page in enumerate(doc):
        pix = page.get_pixmap(dpi=dpi)
        p = f"{out_dir}/p{i+1:03d}.{fmt}"
        pix.save(p, jpg_quality=quality) if fmt == "jpg" else pix.save(p)
        out.append(p)
    return out
```

两个易踩的坑：

- **DPI 低于 150 时，双栏论文的栏间距会糊连**，模型容易把左栏末尾与右栏开头读成一句话。150 是精读的下限，180 更稳。
- **不要用 WebP**。部分视觉编码器对 WebP 的色度子采样处理不一致，细线表格会丢线。

---

## 4. Pass 1：结构扫描

输入全篇低 DPI 图，只问一件事：**每一页是什么**。

输出结构：

```json
{
  "title": "…",
  "sections": [
    {"name": "Abstract", "pages": [1]},
    {"name": "Introduction", "pages": [1, 2]},
    {"name": "Method", "pages": [3, 4, 5, 6]},
    {"name": "Experiments", "pages": [7, 8, 9, 10, 11]},
    {"name": "Conclusion", "pages": [12]}
  ],
  "figure_pages": [4, 8, 9],
  "table_pages": [7, 10]
}
```

这一步不要求任何内容准确性，只要求页码定位对。它便宜（约 2 万 token），且为下一步省钱——精读只跑方法和实验，不必跑引言与相关工作。

`figure_pages` / `table_pages` 单独标出来，是因为图表页需要最高 DPI。

---

## 5. Pass 2 + 3：精读与生成

### 5.1 精读的输入

只取 Method 与 Experiments 章节的页面，180 DPI，连同 Pass 1 的章节地图一起给模型，让它知道自己在读哪一节。

对图页额外传入：该页的图注所在位置说明（"第 8 页含 Figure 3 与时序曲线"），模型对图的理解会明显变好。

### 5.2 输出数据结构

这是全项目最重要的契约，后续的指标对比、主题聚类、跨文献检索都建在它上面。

```json
{
  "meta": {
    "title": "",
    "authors": [],
    "venue": "",
    "year": 2025,
    "doi": "",
    "page_count": 24
  },
  "gist": "一句话要旨，不超过 60 字",
  "problem": { "text": "", "page": 1 },
  "method_steps": [
    { "name": "预训练语料", "detail": "", "page": 3 }
  ],
  "findings": [
    { "metric": "mIoU", "value": "+12.4%", "dataset": "LoveDA", "page": 8 }
  ],
  "limits": { "text": "", "page": 12 },
  "topics": [{ "name": "基础模型", "confidence": 0.91 }],
  "confidence": {
    "overall": 0.86,
    "weak_fields": ["limits"]
  }
}
```

三个字段值得单独说明：

**`findings` 是三元组而非段落**。`metric + value + dataset` 必须成组出现。理由不是校验，而是产品价值——只有结构化到这一层，才可能做出「跨论文指标对比表」。这件事是纯文字摘要工具做不到的，也是这个产品真正的壁垒。

**`page` 字段贯穿每个结论**。用户能看到结论出自第几页，一键跳原文。这是零成本的信任设计，也是纯视觉路线唯一必须保留的保险。

**`confidence.weak_fields`** 让模型自己说哪些字段它没把握。UI 上把这些字段标灰，比事后加校验链路便宜得多，用户感知却更强。

### 5.3 Prompt 骨架

```
system:
你是遥感与地理信息领域的论文审读者。你的任务是从页面图像中抽取结构化信息。

硬性规则：
1. 只输出 JSON，不加任何解释文字。
2. 所有数值必须逐字来自原文。看不清或没有就填 null，禁止推测、禁止换算单位。
3. 每个字段必须给出所在页码。
4. findings 最多 4 条，只保留作者在正文中明确强调的结果，
   不取图表中未在文字里提到的数字。
5. limits 必须来自作者自述的局限或讨论章节，
   不要用你的领域知识补充作者没说的话。

user:
[章节地图 JSON]
现在精读 Method（p3–p6）与 Experiments（p7–p11）。
[页面图像 × N]
按给定 schema 输出 JSON。
```

第 4、5 条是这个 prompt 里最重要的两句。**限制 findings 只取正文强调的结果**，能把大量"图表里有但作者没主张"的数字挡在外面——这类数字是幻觉的主要来源，也是用户拿去对比时最容易出错的地方。**limits 只取作者自述**，防止模型用自己的常识编造局限，那不是这篇论文的问题陈述，学术上不成立。

## 6. 成本模型

以 24 页双栏期刊论文计：

| 阶段 | 输入 token | 说明 |
|---|---|---|
| Pass 1 结构扫描 | ~20,000 | 24 页 × 800 |
| Pass 2 精读 | ~32,000 | 约 9 页 × 3,500 |
| Pass 3 生成 | ~40,000 | 累计上下文 |
| **合计** | **~92,000** | |

按 $0.14 / M 输入 token：单篇约 **$0.013**，合人民币 **0.09 元**。若开启缓存命中，可降至 0.05 元以内。

一千篇文献约 90 元，一万篇约 900 元。这个量级允许把全库重跑当作常规运维手段——模型升级后重新解析全库，成本可接受，这是纯视觉路线相对本地 pipeline 的隐性优势：**没有本地组件版本债，模型换代即全库收益**。

---

## 7. 质量保障（最小集）

不做校验链路，但保留三条零成本措施：

| 措施 | 成本 | 作用 |
|---|---|---|
| 每条结论带页码 | 0 | 用户可一键核对，信任有落点 |
| 模型自评 `weak_fields` | 0 | 把不确定性显式化，UI 可标灰 |
| `findings` 只取正文强调 | 0 | 挡住图表数字幻觉的主要来源 |

这三条都不增加调用次数，也不引入外部依赖，符合"完全相信模型"的架构选择。区别在于：**相信模型，但让用户看得见模型在哪里可能不可靠**。这不是技术保守，是产品诚实。

---

## 8. 失败模式与降级

| 现象 | 成因 | 处理 |
|---|---|---|
| 双栏串行 | DPI 过低 | 精读强制 ≥180 DPI |
| 公式语义错误 | 纯视觉固有限制 | 保留公式截图，不转写，正文中标注「见原文 p3 式(2)」 |
| 表格行列错位 | 复杂表头 | 表格整体作为图片存入要义页，不做转写 |
| 数字读错 | 模型幻觉 | 靠页码让用户自查；高频出错的主题下加人工抽检 |
| 扫描版 PDF | 无差别，本就靠视觉 | 无需特殊处理，这是纯视觉路线意外的优势 |

最后一行值得注意：**扫描版与电子版在纯视觉路线下没有区别**。传统 pipeline 要为扫描件单独做 OCR 分支，这里不需要。

---

## 9. 实施顺序

1. 渲染模块（半天）：PDF → 页图，验证 DPI 与双栏切割
2. Pass 1 结构扫描（半天）：能稳定输出正确页码地图
3. Pass 2/3 抽取（1–2 天）：schema 落地，跑通 5 篇
4. 评测（1 天）：20 篇 benchmark，见第 10 节
5. 入库与索引（2 天）：结构化 JSON → 本地库，支持按指标/主题检索

前四步约四天可出可用版本。

---

## 10. 评测基准

不要凭感觉判断这条路走不走得通，用数据。

**样本**：20 篇本领域论文，覆盖三类——公式密集（辐射传输类）、图表密集（时序分析类）、方法简单（应用类）。

**标注**：人工填写要义页五个字段作为 ground truth。

**三个指标**：

| 指标 | 定义 | 及格线 | 目标 |
|---|---|---|---|
| 数字准确率 | findings 中数值与原文一致的比例 | ≥97% | ≥99% |
| 章节归属准确率 | 方法步骤未跨节错配的比例 | ≥95% | ≥98% |
| 方法完整率 | 人工三步中模型覆盖的比例 | ≥85% | ≥92% |

若数字准确率低于 95%，先怀疑渲染参数而非模型。**顺序是：先调 DPI，再调 prompt，最后才怀疑路线。**

---

## 11. 已知取舍

诚实记录这条路线放弃的东西，供日后复盘：

- **放弃字符级精确**：数字正确率上限低于文本层方案，这是结构性代价，不是实现问题。
- **放弃公式可计算性**：公式只能看不能算，无法做跨论文的公式级比对。
- **放弃离线能力**：全部解析依赖 API，断网即不可用，与产品宣称的「本地解析」存在冲突，需要在文案上调整（改为「原文不出本机，仅上传页面图像」——这本身就是事实）。
- **成本随篇数线性增长**：不像本地 pipeline 有边际成本归零的可能。
